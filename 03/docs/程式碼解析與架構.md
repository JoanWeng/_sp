# EmoLang 程式碼解析與架構

## 目錄結構

```
.
├── emolang.py              # 主程式（Tkinter GUI 編輯器）
├── emolang_lsp.py          # LSP 伺服器（語法突顯、診斷、程式碼補全）
```

## 整體處理管線

```
原始碼 (.emo)
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  1. Lexer (詞法分析)  — EmoLangLexer.advance()      │
│     原始碼字串 → Token 串流                          │
│     用於：一般執行、GUI 語法突顯（get_tokens）        │
└──────────────────────┬──────────────────────────────┘
                       │ Token 串流
                       ▼
┌─────────────────────────────────────────────────────┐
│  2. Parser (語法分析)  — EmoLangParser               │
│     Token 串流 → AST 節點樹                           │
│                                                      │
│     ┌─ 一般模式 (parse/parse_statement)              │
│     │   └ CLI / GUI 執行按鈕 → 立即拋錯              │
│     └─ 診斷模式 (diag_parse/_diag_parse_statement)   │
│         └ GUI 語法檢查 → 收集所有錯誤，繼續解析       │

│     AST 節點樹 → 輸出結果                            │
│     遞迴走訪 AST，對每個節點呼叫 eval/execute        │
└─────────────────────────────────────────────────────┘
```

## 1. `tokens.py` — Token 類型與資料結構

### TokenType（靜態類別，46 個常數）

所有 token 類型以字串常數表示，分為以下群組：

```python
# 關鍵字陳述式
TOK_LET = "LET"       # 📦 🔢 🎈 📝 🚦 變數宣告
TOK_PRINT = "PRINT"   # 📢 輸出
TOK_IF = "IF"         # 🤔 條件判斷
TOK_ELSE = "ELSE"     # 🤷 否則
TOK_WHILE = "WHILE"   # 🔁 條件迴圈
TOK_FOR = "FOR"       # 🎡 計數迴圈
TOK_SEP = "SEP"       # 🚧 分隔符號（for 迴圈用）

TOK_FUNC = "FUNC"     # 🛠️ 函式定義
TOK_RETURN = "RETURN" # 🔙 回傳
TOK_STRUCT = "STRUCT" # 🏗️ 結構體定義

# 運算子
TOK_PLUS = "PLUS"     # ➕ 加法 / 字串串接
TOK_MINUS = "MINUS"   # ➖ 減法
TOK_MUL = "MUL"       # ✖️ 乘法
TOK_DIV = "DIV"       # ➗ 整數/浮點除法
TOK_MOD = "MOD"       # ✂️ 取餘數
TOK_ASSIGN = "ASSIGN" # 🟰 賦值

# 比較與邏輯
TOK_EQ = "EQ"         # 🤝 等於
TOK_GT = "GT"         # 📈 大於
TOK_LT = "LT"         # 📉 小於
TOK_AND = "AND"       # 🔗 邏輯 AND（短路）
TOK_OR = "OR"         # 🔀 邏輯 OR（短路）
TOK_NOT = "NOT"       # 🙅 邏輯 NOT

# 指標與記憶體
TOK_REF = "REF"       # 📍 取址
TOK_DEREF = "DEREF"   # 🎯 解參考
TOK_ARRAY = "ARRAY"   # 📚 陣列配置
TOK_INDEX = "INDEX"   # 📌 索引（[] 代替）

# 資料結構
TOK_NEW = "NEW"       # 🆕 建立實例
TOK_DOT = "DOT"       # ➡️ 成員存取
TOK_LIST = "LIST"     # 📋 列表
TOK_DICT = "DICT"     # 📖 字典
TOK_APPEND = "APPEND" # 🛒 列表追加元素
TOK_LEN = "LEN"       # 📏 長度計算

# 字面值
TOK_NUM = "NUM"       # 整數
TOK_FLOAT_NUM = "FLOAT" # 浮點數
TOK_STR = "STR"       # 字串
TOK_TRUE = "TRUE"     # 🟢 真
TOK_FALSE = "FALSE"   # 🔴 假
TOK_ID = "ID"         # 識別字（變數/函式名稱）

# 其他
TOK_LPAREN = "LPAREN"   # (
TOK_RPAREN = "RPAREN"   # )
TOK_COMMA = "COMMA"     # ,
TOK_LBRACE = "LBRACE"   # 👇 區塊開始
TOK_RBRACE = "RBRACE"   # 👆 區塊結束
TOK_INPUT = "INPUT"     # 📥 讀取輸入
TOK_EOF = "EOF"         # 結尾
```

### Token 類別

```python
class Token:
    type: str        # TokenType 字串（如 "PRINT"、"NUM"）
    value: str       # 原始碼中的字面值（如 "📢"、"42"）
    line: int        # 行號（1-based）
    col: int         # 欄號（1-based）
    length: int      # UTF-8 位元組長度
    char_length: int # 字元長度（用於 Tcl/Tk 語法突顯定位）
```

**為什麼需要 `char_length`？** Tcl/Tk 文字元件（Text widget）使用 UCS-2（或 UTF-16）計算字元位置，而 emoji 是 surrogate pair（佔 2 個 Tcl 字元單位）。`char_length` 就是從 Python 角度看到的字元數量，用於 `text.tag_add(tag, start, end)` 時準確定位 emoji token 的結束位置。

### `tokenize()` 便利函式

```python
def tokenize(code):
    """直接從原始碼產生完整 Token 列表"""
    lexer = EmoLangLexer(code)
    tokens = []
    lexer.advance()
    while lexer.current_token.type != TokenType.TOK_EOF:
        tokens.append(lexer.current_token)
        lexer.advance()
    tokens.append(lexer.current_token)
    return tokens
```

## 2. `lexer.py` — 詞法分析器

### `EmoLangLexer`

採用手動狀態機，逐字元掃描原始碼。不使用正則表達式，因為 emoji 為多 byte UTF-8 序列，正則處理跨 byte 邊界複雜，且手動模式可精確控制位置追蹤與錯誤訊息。

#### 狀態

```python
self.src  # 原始碼字串
self.pos  # 目前掃描位置（位元組索引）
self.line  # 目前行號（1-based）
self.col  # 目前欄號（1-based）
self.current_token  # 上一個 advance() 產生的 Token
```

#### Emoji 關鍵字表（`self.emoji_keywords`）

54 個 emoji → token 類型的對應字典。每個 emoji 為 key，token 類型字串為 value。用 `match_keyword()` 在目前位置比對：

```python
def match_keyword(self):
    for kw in self.emoji_keywords:
        if self.src.startswith(kw, self.pos):
            return kw
    return None
```

注意：比對順序依賴 dict 的插入順序（Python 3.7+），因此短 emoji（如 `➕`）和長 emoji（如 `🏗️` 4-byte + VS16）都能正確比對。

#### `advance()` 完整流程

```python
def advance(self):
    # 1. 跳過空白字元，遇到 \n 更新 line/col
    self.skip_space()
    # 2. 檢查 EOF
    if self.pos >= len(self.src):
        tok = Token(TOK_EOF, "", line=self.line, col=self.col, length=0)
        self.current_token = tok
        return

    # 3. 記錄目前位置（給 _emit 用）
    self._start_line = self.line
    self._start_col = self.col

    # 4. 單字元符號
    if ch == '(':  → TOK_LPAREN
    if ch == ')':  → TOK_RPAREN
    if ch == ',':  → TOK_COMMA
    if ch in '[]': → RuntimeError (不支援)

    # 5. 字串常數（以 " 開頭）
    if ch == '"':
        -> 收集字元直到遇到下一個 "
        -> 支援跳脫序列：\n → \n, \\ → \\, \" → "
        -> 跨行字串 → RuntimeError
        -> EOF 未閉合 → RuntimeError
        -> TOK_STR

    # 6. 數字字面值（以 digit 開頭）
    if ch.isdigit():
        -> 收集數字與 . (小數點)
        -> 若 . 出現則為 TOK_FLOAT_NUM，否則 TOK_NUM
        -> 禁止數字後接字母/數字（如 123abc）→ RuntimeError

    # 7. Emoji 關鍵字
    kw = match_keyword()
    if kw:
        -> 對應 TokenType，記錄原始碼位置
        -> UTF-8 byte_len 與 char_len 分別計算

    # 8. 識別字（其餘情況）
    -> 收集非空白、非關鍵字、非括號逗號的字元
    -> 禁止以數字開頭 → RuntimeError
    -> 禁止以特殊符號開頭（@, # 等）→ RuntimeError
    -> TOK_ID
```

#### 位置追蹤機制

每次 `advance()` 開始前，將目前 `self.line` / `self.col` 存入 `self._start_line` / `self._start_col`。每個 token 的 `line` / `col` 就是該 token 的起始位置，1-based。`_emit()` 方法將這些值填入 Token 物件的對應欄位：

```python
def _emit(self, tok_type, value, byte_length, char_length=None):
    tok = Token(tok_type, value, line=self._start_line, col=self._start_col,
                 length=byte_length, char_length=char_length or byte_length)
    return tok
```

#### 錯誤處理策略

所有 lexer 錯誤均拋出 `RuntimeError`（不含未閉合字串、不支援符號、非法識別字等）。呼叫方需自行處理：

- 在 `parse()` / `parse_statement()` 中：讓錯誤向上傳播至 evaluator，中斷執行
- 在 `diag_parse()` / `_diag_parse_statement()` 中：catch `RuntimeError`，記錄到 `self.diag_errors`，跳至下一語句
- 在 `get_tokens()`（emolang_lsp.py）中：catch `RuntimeError`，跳過 1 字元後重試，確保語法突顯不受單一錯誤影響

### ASTNode 類別

```python
class ASTNode:
    type: str       # ASTType 字串常數
    line, col: int  # 原始碼位置（對應起始 token 位置）

    # 二元運算
    op: str         # 運算子 TokenType（如 TOK_PLUS、TOK_EQ）

    # 名稱（變數、函式、結構體、字串）
    name: str

    # 數值
    value: int      # 整數值（AST_NUM）
    f_val: float    # 浮點數值（AST_FLOAT）

    # 左右子樹（二元運算、賦值、一元運算）
    left: ASTNode
    right: ASTNode

    # 控制流
    cond: ASTNode          # 條件（FOR 用）
    step: ASTNode          # 遞增（FOR 用）
    true_branch: [ASTNode]  # IF/WHILE 的成立分支主體
    false_branch: [ASTNode] # IF 的不成立分支主體
    body: [ASTNode]         # 函式/迴圈/區塊的主體

    # FUNC_CALL 特殊使用
    # node.left = [ASTNode, ...]  # 參數列表
    # node.name = function_name
```

設計特點：單一類別透過不同欄位組合表示所有節點型態，類似 C 語言的 union（但以 Python 動態屬性實現），而非傳統的類別繼承。優點是簡潔，缺點是執行時期需要檢查 `node.type` 決定使用哪些欄位。

## 4. `parser.py` — 語法分析器

### `EmoLangParser`

將 Token 串流轉換為 AST 節點樹。以遞迴下降（recursive descent）實作，包含兩套完全獨立的解析路徑。

#### 運算子優先級表（從低到高）

```
層級 0: parse_expression      → OR  (🔀)     ← 最低優先級
層級 1: parse_logical_and     → AND (🔗)
層級 2: parse_comparison      → EQ (🤝) / GT (📈) / LT (📉)
層級 3: parse_addition        → PLUS (➕) / MINUS (➖)
層級 4: parse_factor          → MUL (✖️) / DIV (➗) / MOD (✂️)
層級 5: parse_prefix          → 前綴 + 後綴DOT/INDEX
層級 6: parse_prefix_only     → NOT / INPUT / REF / DEREF / LEN / NEW
層級 7: parse_primary         → 括號 / NUM / FLOAT / TRUE / FALSE / STR / ID / FUNC_CALL
```

每個層級先呼叫下一層級解析左運算元，再以 while 迴圈處理相同優先級的運算子。

**短路求值**：`🔀` (OR) 若左運算元為 truthy 則回傳 true 不計算右運算元；`🔗` (AND) 若左運算元為 falsy 則回傳 false 不計算右運算元。短路在 evaluator 實作，parser 只負責 AST 結構。

#### 語句解析

`parse_statement()` 依 token 類型分派：

```
TOK_FUNC   → 🛠️ name(params) 👇 body 👆
TOK_RETURN → 🔙 expr
TOK_LET    → 📦 name 🟰 expr
TOK_PRINT  → 📢 expr
TOK_IF     → 🤔 cond 👇 ... 👆 🤷 👇 ... 👆
TOK_WHILE  → 🔁 cond 👇 ... 👆
TOK_FOR    → 🎡 init 🚧 cond 🚧 step 👇 ... 👆
TOK_STRUCT → 🏗️ Name 👇 fields 👆
expr       → 表達式（若後有 🟰 → ASSIGN，有 🛒 → APPEND）
```

#### 診斷模式（`diag_parse()`）

用於 GUI 一次性收集所有語法錯誤，而非遇到第一個錯誤就停止。核心設計：

```
1. 初始化錯誤清單 self.diag_errors = [] 與已宣告變數集合 self._declared_vars = set()
2. 進入主迴圈，每次處理一個語句：
   a. 若目前 token 是陳述式起始符號 → 呼叫 _diag_parse_statement()
   b. 否則 → 記錄「多餘的 token」錯誤，跳到下一個 token
3. _diag_parse_statement() 內所有 advance() 以 try/except RuntimeError 保護
4. 語句解析失敗時，記錄錯誤並跳至下一個語句起始符號
```

**關鍵對比：一般 vs 診斷**

| 特性 | 一般模式 | 診斷模式 |
|------|----------|----------|
| 錯誤處理 | 拋出 RuntimeError 終止 | 記錄至 diag_errors + 跳過恢復 |
| 錯誤數量 | 1 個即停止 | 最多收集 100 個 |
| 變數追蹤 | 不追蹤（執行時期才檢查） | 追蹤 `_declared_vars` + 遞迴檢查未宣告變數 |
| 遺漏運算子 | 拋錯 | 記錄錯誤後 consume 額外表達式避免級聯 |
| 錯誤恢復 | 不適用 | `_diag_skip_to_statement()` 跳到下一語句起始 |

**錯誤恢復策略 — `_diag_skip_to_statement()`：**

當遇到無法解析的名稱時，跳過該名稱 token 及其後直到遇到下一個語句起始符號（排除 `👉` `👆` `(`，因為這些可能是區塊或括號內容）:

```python
def _diag_skip_to_statement(self):
    self.lexer.advance()  # skip the invalid name token
    while self.lexer.current_token.type != TokenType.TOK_EOF:
        t = self.lexer.current_token.type
        if t in _STATEMENT_STARTERS and \
           t not in (TOK_LBRACE, TOK_RBRACE, TOK_LPAREN):
            break
        self.lexer.advance()
```

**連續表達式錯誤處理：**

```python
# 在診斷模式下，若同一行接連出現多個表達式（無運算子）：
if expr.type in _BARE_EXPR_TYPES:
    self.diag_errors.append((expr.line, "語法錯誤: 少了 📢"))
if self.lexer.current_token.type in _EXPR_STARTERS and \
   self.lexer.current_token.line == expr.line:
    self.diag_errors.append((expr.line, "語法錯誤: 連續表達式缺少運算子"))
    # 消耗本行剩餘表達式，避免同一行噴多次相同錯誤
    while self.lexer.current_token.type in _EXPR_STARTERS and \
          self.lexer.current_token.line == expr.line:
        try:
            self.parse_expression()
        except RuntimeError:
            self.lexer.advance()
```

**缺失區塊起始符號 (`👇`) 處理：**

```python
def _diag_parse_block(self):
    if self.lexer.current_token.type != TOK_LBRACE:
        tok = self.lexer.current_token
        self.diag_errors.append((tok.line, f"語法錯誤: 期待 LBRACE，但遇到 {tok.type}"))
        return []  # 回傳空區塊，讓解析繼續
```

**缺失右大括號處理：**

若掃到 EOF 仍未見到 `👆`，記錄錯誤並回傳已收集的語句。

#### 控制變數宣告追蹤

診斷模式維護 `self._declared_vars` 集合，在以下情況加入變數名稱：
- `📦 x` → `self._declared_vars.add("x")`
- `x 🟰 ...`（賦值表達式） → `self._declared_vars.add("x")`

當遇到 `📢`（PRINT）、`🤔`（IF）、`🔁`（WHILE）、`🔙`（RETURN）時，遞迴檢查其子樹中的變數節點是否在 `_declared_vars` 中：

```python
def _diag_check_undeclared_vars(self, node):
    if node is None:
        return
    if node.type == ASTType.AST_VAR:
        if node.name not in self._declared_vars:
            self.diag_errors.append((node.line,
                f"語法錯誤: 未宣告變數「{node.name}」"))
    for child in [node.left, node.right, node.cond, node.step]:
        if child is not None:
            if isinstance(child, list):
                for c in child:
                    self._diag_check_undeclared_vars(c)
            else:
                self._diag_check_undeclared_vars(child)
```

## 5. `evaluator.py` — 執行引擎

### `EmoLangEvaluator`

遞迴走訪 AST，對每個節點執行對應運算。使用 C 語言風格的記憶體模型。

#### 記憶體模型

```python
self.memory: {int → Value}      # 堆積：位址 → 值
self.heap_ptr: int               # 下一個可用位址（從 1 開始遞增）
self.sym_stack: [{str → int}]    # 符號表堆疊：名稱 → 位址
```

- **`memory`** 是一個 dict，所有變數的值都存放在此。key 是整數位址，value 是 `Value` 物件。
- **`heap_ptr`** 從 1 開始，每次 `alloc_mem(size)` 時回傳目前值並將 heap_ptr 加上 size。
- **`sym_stack`** 是一個 list of dict。外層變數宣告壓入最頂層 dict；函式呼叫時建立新層（push），返回時 pop。

**記憶體配置：**

```python
def alloc_mem(self, size):
    addr = self.heap_ptr
    self.heap_ptr += size
    return addr
```

**符號查詢（從內往外搜尋）：**

```python
def get_sym_addr(self, name):
    for i in range(len(self.sym_stack) - 1, -1, -1):
        if name in self.sym_stack[i]:
            return self.sym_stack[i][name]
    raise NameError(f"名稱 '{name}' 未定義")
```

**賦值機制：**

```python
def assign_value(self, node, val):
    if node.type == AST_VAR:
        try:
            self.memory[self.get_sym_addr(node.name)] = val
        except NameError:
            addr = self.alloc_mem(1)
            self.sym_stack[-1][node.name] = addr  # 動態宣告
            self.memory[addr] = val
    elif node.type == AST_DEREF:
        self.memory[self.eval(node.left).i] = val    # 寫入位址
    elif node.type == AST_DOT:
        obj_addr = self.eval(node.left).i
        sid = self.memory[obj_addr].i                # struct id
        field_addr = obj_addr + 1 + sd["fields"].index(node.name)
        self.memory[field_addr] = val
    elif node.type == AST_INDEX:
        base = self.eval(node.left)                   # 列表/陣列基底
        idx = self.eval(node.right)
        if base.type == 3:  # list
            self.list_pool[base.i]["items"][idx.i] = val
        elif base.type == 4:  # dict
            self.dict_set(base.i, idx.s, val)
        else:  # buffer (raw memory)
            self.memory[base.i + idx.i] = val
```

#### 全域狀態

```python
self.struct_table: {int → {"name", "fields", "field_count"}}
self.func_table: {str → {"params", "body"}}
self.call_depth: int         # 防止堆疊過深
self.ret_val: Value          # 回傳值緩衝
self.is_returning: bool      # 回傳標記
self.output: [str]           # 📢 輸出列表
self.input_callback: callable # 📥 使用者輸入回呼
self.list_pool: [{"items": [Value; 100], "count": int}]
self.dict_pool: [{"keys": [str; 100], "values": [Value; 100], "count": int}]
```

#### `eval()` 方法（回傳 Value）

對每個 AST 節點類型的處理：

**葉節點：**
- `AST_NUM` → `Value(type=0, i=node.value)`
- `AST_FLOAT` → `Value(type=1, f=node.f_val)`
- `AST_STR` → `Value(type=2, s=node.name)`
- `AST_TRUE` / `AST_FALSE` → `Value(type=0, i=1/0)`
- `AST_VAR` → `self.memory[self.get_sym_addr(node.name)]`

**一元運算：**
- `AST_NOT` → eval child → `i = 0 if is_truthy(val) else 1`
- `AST_REF` → 回傳變數的位址（`Value(type=0, i=addr)`）
- `AST_DEREF` → eval child 取得位址 → 讀取 `memory[位址]`
- `AST_LEN` → 回傳字串/列表/字典的長度
- `AST_INPUT` → 呼叫 `input_callback()` 或 `input()`，自動判斷類型
- `AST_NEW_LIST` → 從 `list_pool` 分配，回傳 `Value(type=3, i=list_id)`
- `AST_NEW_DICT` → 同上，`type=4, i=dict_id`
- `AST_ARRAY_ALLOC` → `alloc_mem(eval(child).i)`

**二元運算（`AST_BINOP`）：**
1. `🔗` (AND)：先 eval left，若 falsy 直接回傳 false（短路）
2. `🔀` (OR)：先 eval left，若 truthy 直接回傳 true（短路）
3. 其餘：eval left + right → 依 `node.op` 計算：
   - `➕` (PLUS)：若任一運算元為字串 → 字串串接
   - 若任一運算元為浮點數 → 浮點數運算
   - 否則 → 整數運算
   - 整數除法使用 `//`（floor division）
4. 特定運算子 → 根據 `Value.type` 決定行為：
   - `type=0`（int）：直接操作 `.i`
   - `type=1`（float）：轉換為 `.f` 後運算
   - `type=2`（str）：僅 `➕` 支援串接

**成員與索引：**
- `AST_DOT` → `self.memory[self.get_lvalue(node)]`
- `AST_INDEX` → 根據基底類型分派（list/dict/buffer）

**函式呼叫：**

```python
if node.type == AST_FUNC_CALL:
    fd = self.func_table[node.name]
    arg_vals = [self.eval(arg) for arg in node.left]

    self.call_depth += 1
    self.sym_stack.append({})  # 推入新作用域

    # 參數傳遞：alloc_mem + 填入值
    for j, p in enumerate(fd["params"]):
        if j < len(arg_vals):
            addr = self.alloc_mem(1)
            self.sym_stack[-1][p.name] = addr
            self.memory[addr] = arg_vals[j]

    self.execute(fd["body"])  # 執行函式主體

    if self.is_returning:
        res = self.ret_val
        self.is_returning = False

    self.call_depth -= 1
    self.sym_stack.pop()  # 彈出作用域
```

#### `execute()` 方法（不直接回傳值）

對每個陳述式節點的處理：

| AST 類型 | 行為 |
|----------|------|
| `AST_RETURN` | eval 左子樹 → 存入 `self.ret_val`，設定 `self.is_returning = True`，return |
| `AST_FUNC_DEF` | 將函式定義存入 `self.func_table[name]` |
| `AST_LET` | alloc_mem(1) → sym_stack 登記 → 若有初始值則 eval 並儲存 |
| `AST_ASSIGN` | `self.assign_value(node.left, self.eval(node.right))` |
| `AST_APPEND` | eval 左（列表）→ 右（值）→ `list_pool[id]["items"][count] = val` |
| `AST_STRUCT_DEF` | 解析 body 中的 LET 語句建立欄位列表 → 存入 `self.struct_table` |
| `AST_PRINT` | eval 左子樹 → 依 type 格式化 → append 到 `self.output` |
| `AST_IF` | eval 條件 → truthy → execute(true_branch)，否則 execute(false_branch) |
| `AST_WHILE` | while 條件為 truthy → execute(body) |
| `AST_FOR` | execute(init) → while cond truthy → execute(body) → execute(step) |

#### `run()` 方法（完整管線）

```python
def run(self, code, input_callback=None):
    self.reset()                       # 清除所有狀態
    self.input_callback = input_callback

    lexer = EmoLangLexer(code)         # 建立 Lexer
    parser = EmoLangParser(lexer)      # 建立 Parser
    statements = parser.parse()        # 一般解析
    self.execute(statements)           # 遞迴執行

    return "\n".join(self.output)      # 回傳所有 📢 輸出
```

## 6. `runtime.py` — 值系統

```python
class Value:
    type: int   # 0=int, 1=float, 2=str, 3=list ref, 4=dict ref
    i: int      # 整數值
    f: float    # 浮點數值
    s: str      # 字串值
```

- `type=0`：整數（`i` 有效）
- `type=1`：浮點數（`f` 有效）
- `type=2`：字串（`s` 有效）
- `type=3`：列表參考（`i` 為 `list_pool` 索引）
- `type=4`：字典參考（`i` 為 `dict_pool` 索引）

**truthy 判斷：**

```python
def is_truthy(self, v):
    if v.type == 0: return v.i != 0
    elif v.type == 1: return v.f != 0.0
    elif v.type == 2: return len(v.s) > 0
    return 0  # list/dict ref always false
```

## 7. GUI 整合（`emolang.py`）

Tkinter 文字編輯器，負責語法突顯、錯誤標記、執行、折疊。透過上述 `emolang/src/` 模組取得所有分析結果。

### 語法突顯（`_apply_semantic_highlighting()`）

1. **清空所有 tags** → 確保不會殘留舊的顏色
2. **呼叫 `get_tokens(code)`**（在 `emolang_lsp.py`）取得所有 token
3. **為每個 token 建立/套用顏色 tag**：
   - 關鍵字（`📢`、`🤔` 等）→ 各自的 `tok_LET`、`tok_PRINT` 等
   - 數字 → `number` tag
   - 字串 → `string` tag
   - 運算子 → `operator` tag
4. **診斷解析**：呼叫 `parser.diag_parse()` 收集錯誤
   - 只在非折疊狀態時執行
   - 取得第一個錯誤（`diag_errors[0]`）在狀態列顯示
5. **錯誤標記**：
   - `error_tag`：tag_configure 最低優先級（背景 `#5a2020` + 底線）
   - `error_gutter`：行號區紅色標記

### `get_tokens()` 錯誤恢復（`emolang_lsp.py:109-129`）

```python
def get_tokens(code):
    tokens = []
    lexer = EmoLangLexer(code)
    while True:
        try:
            lexer.advance()
        except RuntimeError:
            if lexer.pos < len(lexer.src):
                ch = lexer.src[lexer.pos]
                lexer.pos += 1
                if ch == '\n':
                    lexer.line += 1      # 關鍵：跳過 \n 時更新行號
                    lexer.col = 1
                else:
                    lexer.col += 1
                continue                 # 跳過 1 字元後重試
            break
        if lexer.current_token is None or lexer.current_token.type == TOK_EOF:
            break
        tokens.append(lexer.current_token)
    return tokens
```

**為何這個函式至關重要？**
- 它在 GUI 每次按鍵時被呼叫（用於即時語法突顯）
- 如果跳過 `\n` 時沒有更新 `lexer.line`，後續所有 token 的行號都會錯誤
- 行號錯誤導致 `tag_add(tag, line.col, line.col+len)` 指向不存在的行 → 靜默失敗 → 整段程式碼變成白色（未著色）
- 這就是「折疊後綠色不消 / 檔案變白」的根本原因

### 錯誤標記優先級

Tkinter Text widget 的 tag 優先級由建立順序決定（後建立的優先級較高）：

1. `error_tag`（最先建立）— 最低優先級，背景 + 底線
2. 各語法顏色 tag（`tok_LET`、`number` 等）— 正常優先級，前景覆蓋 error_tag 的前景
3. 折疊 tag（`hidden`）— 最高優先級

因此 `error_tag` 的深紅背景和底線在錯誤 token 上仍然可見，但不會覆蓋語法顏色。

### 折疊（folding）

使用 Text widget 的 `tag_config(hidden=True)` + 行號 sidebar 的 +/- 按鈕實現。

## 10. 程式碼實例追蹤（完整管線）

以 `📢 🤔 📈 3 5 👇 📢 "yes" 👆 📢 "no" 👆` 為例：

```
原始碼 → Lexer → [PRINT(📢), IF(🤔), GT(📈), NUM(3), NUM(5),
                   LBRACE(👇), PRINT(📢), STR("yes"), RBRACE(👆),
                   PRINT(📢), STR("no"), RBRACE(👆)]

→ Parser:

    PRINT
      └── IF
            ├── BINOP(GT)
            │     ├── NUM(3)
            │     └── NUM(5)
            ├── true_branch: [PRINT → STR("yes")]
            └── false_branch: [PRINT → STR("no")]

→ Evaluator:

    execute(AST_PRINT):
      self.eval(AST_IF):
        self.eval(BINOP(GT)):
          left = self.eval(NUM(3))  → Value(0, 3)
          right = self.eval(NUM(5)) → Value(0, 5)
          3 > 5 → false → Value(0, 0)
        is_truthy(Value(0,0)) → false
        execute(false_branch):
          execute(AST_PRINT):
            self.eval(STR("no")) → Value(2, "no")
            self.output.append("no")
    return "\n".join(["no"])
```
