# 第 11 章　編譯器概論

> **本章目標：** 理解編譯器將高階語言翻譯為目的碼的完整流程，涵蓋詞法分析、語法分析、語意分析、中間碼產生與最佳化的核心概念，以及與組譯器在設計上的異同。

---

## 11.1 編譯器的整體架構

### 11.1.1 編譯的階段

編譯器將原始碼翻譯為目的碼，通常分為**前端（Front End）**與**後端（Back End）**：

```
原始碼（C / C++ / Java ...）
        │
        ▼ ──────────────── 前端 ─────────────────
   詞法分析器（Lexer / Scanner）
        │  Token 串流
        ▼
   語法分析器（Parser）
        │  抽象語法樹（AST）
        ▼
   語意分析器（Semantic Analyzer）
        │  標記型別的 AST
        ▼
   中間碼產生器（IR Generator）
        │  中間表示（IR，如 LLVM IR / Three-Address Code）
        ▼ ──────────────── 後端 ─────────────────
   最佳化器（Optimizer）
        │  最佳化後的 IR
        ▼
   程式碼產生器（Code Generator）
        │  目標平台的組合語言 / 機器碼
        ▼
   可執行檔 / 目的碼（.o）
```

**前端**與語言相關（C 前端 vs Java 前端不同），**後端**與目標平台相關（x86 後端 vs ARM 後端不同）。中間表示（IR）是連接兩者的橋樑，使「M 種語言 × N 種平台」只需要 M + N 個模組而非 M × N 個。

### 11.1.2 各階段的輸入輸出

| 階段 | 輸入 | 輸出 |
|------|------|------|
| 詞法分析 | 字元串流 | Token 串流 |
| 語法分析 | Token 串流 | 抽象語法樹（AST）|
| 語意分析 | AST | 標記型別的 AST |
| IR 產生 | 標記型別的 AST | 三位址碼 / SSA |
| 最佳化 | IR | 最佳化的 IR |
| 程式碼產生 | IR | 組合語言 / 機器碼 |

## 11.2 詞法分析（Lexical Analysis）

### 11.2.1 Token 的概念

**詞法分析器（Lexer）** 將原始碼的字元串流切割成有意義的**符記（Token）**，每個 Token 包含類型（Type）和值（Value）。

```c
// 原始碼
int result = a + b * 2;

// 詞法分析後的 Token 串流：
// (KEYWORD,  "int")
// (IDENT,    "result")
// (ASSIGN,   "=")
// (IDENT,    "a")
// (PLUS,     "+")
// (IDENT,    "b")
// (STAR,     "*")
// (INT_LIT,  "2")
// (SEMI,     ";")
```

### 11.2.2 Token 的類型

| 類型 | 範例 | 說明 |
|------|------|------|
| `KEYWORD` | `int`, `if`, `while`, `return` | 語言保留字 |
| `IDENT` | `x`, `my_var`, `foo` | 識別符（變數/函式名）|
| `INT_LIT` | `42`, `0xFF`, `0b1010` | 整數字面值 |
| `FLOAT_LIT` | `3.14`, `1e-5` | 浮點字面值 |
| `STRING_LIT` | `"hello"` | 字串字面值 |
| `CHAR_LIT` | `'A'` | 字元字面值 |
| `OPERATOR` | `+`, `-`, `*`, `/`, `%` | 運算子 |
| `ASSIGN` | `=`, `+=`, `-=` | 賦值運算子 |
| `COMPARE` | `==`, `!=`, `<`, `>` | 比較運算子 |
| `LPAREN` | `(` | 左括號 |
| `RPAREN` | `)` | 右括號 |
| `LBRACE` | `{` | 左大括號 |
| `RBRACE` | `}` | 右大括號 |
| `SEMI` | `;` | 分號 |
| `COMMA` | `,` | 逗號 |
| `EOF` | — | 檔案結束 |

### 11.2.3 詞法分析的實作方式

詞法分析通常以**有限狀態機（DFA / NFA）** 實作，或直接手寫：

```python
# 簡易詞法分析器的狀態機概念
def lex(source: str) -> list:
    tokens = []
    i = 0
    while i < len(source):
        c = source[i]

        # 跳過空白
        if c.isspace():
            i += 1

        # 識別符或關鍵字
        elif c.isalpha() or c == '_':
            j = i
            while j < len(source) and (source[j].isalnum() or source[j] == '_'):
                j += 1
            word = source[i:j]
            kind = 'KEYWORD' if word in KEYWORDS else 'IDENT'
            tokens.append((kind, word))
            i = j

        # 整數字面值
        elif c.isdigit():
            j = i
            while j < len(source) and source[j].isdigit():
                j += 1
            tokens.append(('INT_LIT', source[i:j]))
            i = j

        # 運算子與分隔符
        elif c in '+-*/=;(){}':
            tokens.append(('OP', c))
            i += 1

        else:
            raise ValueError(f"未知字元：{c}")

    tokens.append(('EOF', ''))
    return tokens
```

## 11.3 語法分析（Syntax Analysis / Parsing）

### 11.3.1 文法與語法分析的目標

語法分析器（Parser）根據語言的**文法規則（Grammar）** 將 Token 串流組織成樹狀的**抽象語法樹（AST，Abstract Syntax Tree）**。

**C 語言的部分文法（BNF 格式）：**

```
program   → declaration*
declaration → type IDENT '(' params ')' block   (函式)
            | type IDENT '=' expr ';'             (全域變數)

type      → 'int' | 'char' | 'float' | 'void'

block     → '{' stmt* '}'

stmt      → expr ';'
            | 'if' '(' expr ')' stmt ('else' stmt)?
            | 'while' '(' expr ')' stmt
            | 'return' expr ';'
            | block

expr      → assign
assign    → IDENT '=' expr
            | equality
equality  → comparison (('==' | '!=') comparison)*
comparison→ addition (('<' | '>') addition)*
addition  → multiplication (('+' | '-') multiplication)*
multiplication → unary (('*' | '/') unary)*
unary     → '-' unary | primary
primary   → INT_LIT | IDENT | '(' expr ')'
```

### 11.3.2 AST 的結構

```c
// C 程式碼
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

對應的 AST（簡化）：

```
FuncDef("factorial", params=["n:int"], ret="int")
├── IfStmt
│   ├── condition: BinOp("<=", Var("n"), IntLit(1))
│   └── then: ReturnStmt(IntLit(1))
└── ReturnStmt
    └── BinOp("*", Var("n"),
               FuncCall("factorial",
                         BinOp("-", Var("n"), IntLit(1))))
```

### 11.3.3 解析策略：遞迴下降

**遞迴下降解析（Recursive Descent Parsing）** 是最直觀的手寫解析方式，每個文法規則對應一個函式：

```python
# 遞迴下降解析器片段
class Parser:
    def parse_stmt(self):
        if self.peek() == 'if':
            return self.parse_if()
        elif self.peek() == 'while':
            return self.parse_while()
        elif self.peek() == 'return':
            return self.parse_return()
        else:
            return self.parse_expr_stmt()

    def parse_if(self):
        self.expect('if')
        self.expect('(')
        cond = self.parse_expr()
        self.expect(')')
        then_body = self.parse_stmt()
        else_body = None
        if self.peek() == 'else':
            self.advance()
            else_body = self.parse_stmt()
        return IfNode(cond, then_body, else_body)

    def parse_addition(self):
        left = self.parse_multiplication()
        while self.peek() in ('+', '-'):
            op = self.advance()
            right = self.parse_multiplication()
            left = BinOp(op, left, right)
        return left
```

## 11.4 語意分析（Semantic Analysis）

### 11.4.1 語意分析的任務

語法正確不代表語意正確，語意分析器負責檢查：

```c
int x = "hello";   // ✗ 型別不符（int vs string）
int y = z + 1;     // ✗ 未宣告的變數 z
void foo() { return 5; }  // ✗ void 函式不能回傳值
int a = foo();     // ✗ void 函式的回傳值
int b[10];
b[20] = 1;         // 語意上合法（C 不做邊界檢查）但語意警告
```

### 11.4.2 符號表（Compiler 版本）

編譯器的符號表記錄識別符的：名稱、型別、作用域、位置。

```
符號表（含作用域堆疊）

全域作用域：
  factorial → { type: FuncType(int→int), addr: GLOBAL }
  main      → { type: FuncType(void→int), addr: GLOBAL }

factorial 的局部作用域：
  n         → { type: int, addr: PARAM[0] }

main 的局部作用域：
  result    → { type: int, addr: LOCAL[0] }
  i         → { type: int, addr: LOCAL[1] }
```

**作用域規則（Scope Rules）：**

```c
int x = 10;          // 全域 x

void foo() {
    int x = 20;      // 局部 x（遮蔽全域 x）
    {
        int x = 30;  // 更內層的 x
        printf("%d", x);  // 30（最近的 x）
    }
    printf("%d", x); // 20（foo 的 x）
}

// 查找順序：最內層作用域 → 向外 → 全域
```

### 11.4.3 型別檢查與型別推導

```c
int a = 5;
float b = 3.14;
int c = a + b;    // 需要隱式型別轉換：int + float → float → 截斷成 int

// 編譯器的型別檢查步驟：
// 1. a 的型別：int
// 2. b 的型別：float
// 3. a + b：int + float → 提升為 float（類型提升規則）
// 4. 指派給 int c：float → int（可能截斷，發出警告）
```

## 11.5 中間表示（IR）

### 11.5.1 為什麼需要 IR？

IR（Intermediate Representation）讓最佳化與程式碼產生獨立於語言和目標平台：

```
              前端          IR          後端
C 前端      ────→    ┌──────────┐    ────→   x86 後端
C++ 前端   ────→    │  IR 最佳化│    ────→   ARM 後端
Java 前端  ────→    └──────────┘    ────→   RISCV 後端

不用 IR 的話：C→x86, C→ARM, C++→x86, C++→ARM... 每種組合都要單獨做
有了 IR：M 個前端 + N 個後端 = M+N 個模組（而非 M×N）
```

### 11.5.2 三位址碼（Three-Address Code）

三位址碼（TAC）是最常見的 IR 格式，每條指令最多有三個運算元：

```
格式：  x = y op z   （二元運算）
       x = op y      （一元運算）
       x = y         （複製）
       goto L         （無條件跳躍）
       if x goto L   （條件跳躍）
       call f, n     （函式呼叫，n 個參數）
       return x      （回傳）
       param x       （設定參數）
```

**C 程式碼翻譯為 TAC 的範例：**

```c
// 原始 C 程式碼
int result = (a + b) * (c - d);
```

```
; 翻譯為三位址碼
t1 = a + b
t2 = c - d
t3 = t1 * t2
result = t3
```

```c
// if-else 翻譯
if (x > y) {
    z = x - y;
} else {
    z = y - x;
}
```

```
; 翻譯為三位址碼
    if x <= y goto L_else    ; 條件取反！
    t1 = x - y
    z = t1
    goto L_end
L_else:
    t2 = y - x
    z = t2
L_end:
```

```c
// while 迴圈翻譯
int sum = 0;
int i = 1;
while (i <= 10) {
    sum = sum + i;
    i = i + 1;
}
```

```
; 翻譯為三位址碼
    sum = 0
    i = 1
L_while:
    if i > 10 goto L_end   ; 條件取反
    t1 = sum + i
    sum = t1
    t2 = i + 1
    i = t2
    goto L_while
L_end:
```

### 11.5.3 靜態單賦值（SSA，Static Single Assignment）

SSA 是現代編譯器（LLVM、GCC）使用的 IR 格式，每個變數只被賦值一次：

```
; 普通 TAC（x 被賦值多次）
x = 1
x = x + 2
x = x * 3

; SSA 版本（每個版本用下標區分）
x1 = 1
x2 = x1 + 2
x3 = x2 * 3
```

**SSA 的 φ 函式（Phi Function）** 用於處理控制流程的合併：

```
; if (cond) { x = 1; } else { x = 2; }  後使用 x

; SSA：
if cond goto L_then else goto L_else
L_then:
    x1 = 1
    goto L_merge
L_else:
    x2 = 2
    goto L_merge
L_merge:
    x3 = φ(x1, x2)   ; x3 = x1 若來自 L_then，= x2 若來自 L_else
    use x3
```

## 11.6 最佳化（Optimization）

### 11.6.1 最佳化的層次

```
最佳化可在不同層次進行：

1. 高階最佳化（作用在 AST 或高階 IR）：
   - 內嵌展開（Inlining）
   - 迴圈展開（Loop Unrolling）
   - 常數摺疊（Constant Folding）

2. 中階最佳化（作用在 IR，如 LLVM IR）：
   - 死碼消除（Dead Code Elimination）
   - 公共子表達式消除（CSE）
   - 迴圈不變量外提（LICM）

3. 低階最佳化（作用在機器碼）：
   - 暫存器分配（Register Allocation）
   - 指令選擇（Instruction Selection）
   - 窺孔最佳化（Peephole Optimization）
```

### 11.6.2 常數摺疊（Constant Folding）

在編譯時期直接計算常數表達式：

```c
// 原始程式碼
int x = 2 + 3 * 4;
int y = x * 0;
int z = x + 0;
float f = 1.0 / 0.0;  // 編譯時期計算為 +Inf（IEEE 754）

// 常數摺疊後
int x = 14;      // 2 + 3 * 4 = 14
int y = 0;       // x * 0 = 0（若 x 為常數）
int z = 14;      // x + 0 = x（若 x = 14）
```

### 11.6.3 死碼消除（Dead Code Elimination）

移除永遠不會執行或結果永遠不被使用的程式碼：

```c
// 原始程式碼
int foo(int x) {
    int unused = x * 2;    // 結果從未使用 → 死碼
    if (0) {               // 永遠不執行
        return -1;
    }
    return x + 1;
    int after_return = 5;  // 在 return 之後 → 死碼
}

// 死碼消除後
int foo(int x) {
    return x + 1;
}
```

### 11.6.4 公共子表達式消除（CSE）

避免重複計算相同的表達式：

```c
// 原始程式碼
int a = x * y + z;
int b = x * y - z;

// CSE 後
int temp = x * y;    // x*y 只計算一次
int a = temp + z;
int b = temp - z;
```

### 11.6.5 迴圈最佳化

```c
// ── 迴圈不變量外提（LICM）──
for (int i = 0; i < n; i++) {
    arr[i] = arr[i] * (a + b);  // a+b 是迴圈不變量！
}

// LICM 後
int t = a + b;  // 提到迴圈外
for (int i = 0; i < n; i++) {
    arr[i] = arr[i] * t;
}

// ── 迴圈展開（Loop Unrolling）──
for (int i = 0; i < 100; i++) {
    arr[i] = arr[i] * 2;
}

// 展開 4 次後（減少迴圈控制開銷，改善流水線效率）
for (int i = 0; i < 100; i += 4) {
    arr[i+0] = arr[i+0] * 2;
    arr[i+1] = arr[i+1] * 2;
    arr[i+2] = arr[i+2] * 2;
    arr[i+3] = arr[i+3] * 2;
}

// ── 強度削減（Strength Reduction）──
// 將昂貴的運算換為便宜的等效運算
for (int i = 0; i < n; i++) {
    // 原始：乘法
    arr[i] = i * 4;  // IMUL 每次都算
    // 強度削減：加法（初始化後只做加法）
}
// 削減後
int t = 0;
for (int i = 0; i < n; i++) {
    arr[i] = t;
    t += 4;   // IMUL → ADD
}
```

### 11.6.6 暫存器分配（Register Allocation）

將 IR 中的無限個「虛擬暫存器（Virtual Register）」映射到有限的「實體暫存器（Physical Register）」：

```
問題：IR 可以有無限個臨時變數（t1, t2, t3 ...）
      但 x86-64 只有 16 個通用暫存器（減去 RSP/RBP 等保留的更少）

解法（圖著色演算法）：
  1. 建立「干擾圖（Interference Graph）」：
     若兩個變數的生命週期重疊（同時存活），則它們不能用同一個暫存器
  2. 對干擾圖著色：顏色數 = 可用暫存器數
  3. 若無法著色（顏色不夠），將部分變數「溢出（Spill）」到 Stack
```

```
範例：
t1 = a + b        ; t1 生命週期：1-3
t2 = c * d        ; t2 生命週期：2-4
t3 = t1 + t2      ; t3 生命週期：3-5
result = t3 * e   ; result：5-end

干擾圖：
  t1 -- t2（同時存活）
  t2 -- t3（同時存活）

著色（2 種顏色 = 2 個暫存器）：
  t1 → EAX
  t2 → EBX
  t3 → EAX（t1 已死，可重用）
  result → EAX
```

## 11.7 程式碼產生

### 11.7.1 從 IR 到組合語言

編譯器的後端將 IR 翻譯為目標平台的指令：

```
三位址碼 → x86-64 組合語言

t1 = a + b        →   mov eax, [a]
                       add eax, [b]
                       mov [t1], eax

t2 = t1 * 10      →   mov eax, [t1]
                       imul eax, 10
                       mov [t2], eax

if x > y goto L   →   mov eax, [x]
                       cmp eax, [y]
                       jg  L

return x          →   mov eax, [x]
                       ret
```

### 11.7.2 窺孔最佳化（Peephole Optimization）

在機器碼層面做局部最佳化，針對一小段（窺孔）指令序列：

```asm
; 原始（未最佳化）
MOV EAX, [x]
MOV [x], EAX          ; ← 多餘！剛讀進來又寫回去

; 窺孔最佳化後
MOV EAX, [x]           ; 移除多餘的 MOV [x], EAX

; ── 其他例子 ──
MOV EAX, 0            → XOR EAX, EAX     （更短）
ADD EAX, 1            → INC EAX          （有時更快）
MOV EAX, EAX          → （刪除）          （無意義的自我複製）
PUSH EAX; POP EAX     → （刪除）          （無意義的 push/pop 對）
MUL 2                 → SHL EAX, 1       （移位比乘法快）
MUL 8                 → SHL EAX, 3
```

### 11.7.3 GCC 的最佳化等級

```bash
gcc -O0  hello.c -o hello   # 無最佳化（預設，利於除錯）
gcc -O1  hello.c -o hello   # 基本最佳化
gcc -O2  hello.c -o hello   # 建議生產環境（大多數最佳化）
gcc -O3  hello.c -o hello   # 激進最佳化（含向量化，可能改變行為）
gcc -Os  hello.c -o hello   # 最佳化以縮小體積
gcc -Og  hello.c -o hello   # 最佳化但保持除錯資訊完整

# 觀察不同最佳化等級的組語輸出
gcc -O0 -S hello.c -o hello_O0.s
gcc -O2 -S hello.c -o hello_O2.s
diff hello_O0.s hello_O2.s
```

**-O2 常見的最佳化項目：**
- 函式內嵌（`-finline-functions-called-once`）
- 常數傳播（Constant Propagation）
- 死碼消除
- 公共子表達式消除
- 迴圈不變量外提
- 尾遞迴消除（`-foptimize-sibling-calls`）
- 強度削減

## 11.8 編譯器 vs 組譯器的比較

| 比較項目 | 編譯器 | 組譯器 |
|---------|-------|-------|
| 輸入語言 | 高階語言（C、Java...）| 組合語言（NASM、GAS...）|
| 翻譯比例 | 一條高階語句 → 多條機器指令 | 幾乎一對一 |
| 型別系統 | 有（int、float、struct...）| 無（只有位元寬度）|
| 符號表 | 含型別、作用域、參數 | 只含位址和可見性 |
| 最佳化 | 多種（IR 最佳化、暫存器分配）| 有限（窺孔、指令選擇）|
| 前向參考 | 同樣需要多遍處理 | 兩遍掃描解決 |
| 中間表示 | 必要（IR 解耦前後端）| 通常不需要 |
| 除錯資訊 | 豐富（DWARF，含變數名稱）| 有限 |
| 產生品質 | 通常優於手寫組語（有最佳化）| 由程式設計師控制 |

## 11.9 本章小結

**編譯器架構：**
- 前端（詞法→語法→語意分析）負責理解原始語言，輸出 IR
- 後端（最佳化→程式碼產生）負責針對目標平台輸出高效機器碼
- IR 是橋樑，使 M 語言 × N 平台只需 M+N 模組

**詞法分析：** 字元串流 → Token 串流，以有限狀態機實作

**語法分析：** Token 串流 → AST，依照文法規則（BNF），遞迴下降是最直觀的手寫方式

**語意分析：** 型別檢查、符號表管理（含作用域）、語意錯誤偵測

**中間表示：**
- 三位址碼：每條指令最多三個運算元，易於分析與最佳化
- SSA：每個變數只賦值一次，使資料流分析更精確

**最佳化：** 常數摺疊、死碼消除、公共子表達式消除、LICM、迴圈展開、強度削減、暫存器分配（圖著色）

**程式碼產生：** IR → 指令選擇 → 暫存器分配 → 窺孔最佳化 → 目的碼
