# 第 8 章　組譯器設計

> **本章目標：** 理解組譯器的完整設計原理，包含兩遍掃描的詳細演算法、符號表與重定位表的結構、目的碼格式（ELF），以及與連結器的介面。

---

## 8.1 組譯器的角色與輸入輸出

### 8.1.1 組譯器在工具鏈中的位置

```
原始組語（.asm / .s）
        │
        ▼
  ┌───────────┐
  │  組譯器   │  ← 本章主題
  │ Assembler │
  └───────────┘
        │
        ▼
  可重定位目的碼（.o / .obj）
  ┌─────────────────────────┐
  │  ELF Header              │
  │  .text（機器碼）          │
  │  .data（已初始化資料）     │
  │  .bss（未初始化空間）      │
  │  符號表（Symbol Table）   │
  │  重定位表（Relocation）   │
  │  Section Header Table    │
  └─────────────────────────┘
        │
        ▼  連結器（第 9 章）
  可執行檔（ELF executable）
```

### 8.1.2 組譯器的主要任務

| 任務 | 說明 |
|------|------|
| 語法分析 | 解析助記符、運算元、標號、虛擬指令 |
| 符號表管理 | 記錄每個標號的位址、屬性 |
| 指令翻譯 | 將助記符 + 運算元 → opcode + ModRM + SIB + 立即值 |
| 重定位記錄 | 記錄哪些位置含有需要連結器填入的外部符號位址 |
| 目的碼輸出 | 產生符合 ELF/COFF 格式的 .o 檔 |

## 8.2 兩遍組譯演算法

### 8.2.1 為何需要兩遍？

核心問題：**前向參考（Forward Reference）**。

```asm
    JMP  end_label    ; 此時 end_label 未知 → 無法立刻填入位址
    NOP
    NOP
end_label:
    RET
```

若只掃描一遍，遇到 `JMP end_label` 時尚不知道 `end_label` 的位址，無法產生正確的機器碼。**兩遍掃描**的解法：
- **第一遍**：只計算位址，建立符號表（不產生機器碼）
- **第二遍**：查符號表，翻譯每條指令為機器碼（前向參考已可解析）

### 8.2.2 第一遍（Pass 1）詳細演算法

```
輸入：組語原始碼
輸出：符號表（SYMTAB）

初始化：
    LC（位置計數器）← 0
    SYMTAB ← 空表

對每一行：
    1. 去除空白與註解
    2. 若行為空 → 跳過

    3. 若含標號：
       a. 若標號已在 SYMTAB → 錯誤（重複定義）
       b. 否則 → SYMTAB[標號] = (LC, 區段, 屬性)

    4. 判斷助記符類型：
       a. 機器指令 → 查指令長度表，LC += 指令長度
       b. DB        → LC += 運算元的位元組數
       c. DW        → LC += 運算元數 × 2
       d. DD        → LC += 運算元數 × 4
       e. DQ        → LC += 運算元數 × 8
       f. RESB n    → LC += n
       g. RESD n    → LC += n × 4
       h. EQU       → 記錄常數值（不改變 LC）
       i. SECTION   → 切換區段，LC 視情況重設或切換
       j. GLOBAL    → 標記符號為全域（供連結器使用）
       k. EXTERN    → 記錄外部符號（此檔案中未定義）

結束：輸出 SYMTAB
```

### 8.2.3 指令長度表（Opcode Table）

組譯器在 Pass 1 需要知道每條指令的長度（以便正確計算 LC），這些資訊存在**指令表（OPTAB）**中：

```
指令表（OPTAB，部分）
┌──────────┬─────────┬────────────────────────────────────┐
│ 助記符   │ Opcode  │ 運算元類型 → 長度規則               │
├──────────┼─────────┼────────────────────────────────────┤
│ NOP      │ 90      │ 無運算元 → 1 byte                  │
│ RET      │ C3      │ 無運算元 → 1 byte                  │
│ PUSH r64 │ 50+rd   │ 暫存器 → 1 byte（或 2 with REX）   │
│ POP  r64 │ 58+rd   │ 暫存器 → 1 byte（或 2 with REX）   │
│ MOV r,i32│ B8+rd   │ 暫存器+立即值 → 5 bytes            │
│ MOV r,i64│ REX B8  │ 暫存器+立即值 → 10 bytes           │
│ ADD r,r  │ 01/03   │ 暫存器+暫存器 → 2 bytes            │
│ JMP short│ EB      │ 短跳 → 2 bytes                    │
│ JMP near │ E9      │ 近跳 → 5 bytes                    │
│ JE  short│ 74      │ 條件短跳 → 2 bytes                 │
│ JE  near │ 0F 84   │ 條件近跳 → 6 bytes                 │
│ CALL near│ E8      │ 近呼叫 → 5 bytes                   │
│ SYSCALL  │ 0F 05   │ 無運算元 → 2 bytes                 │
└──────────┴─────────┴────────────────────────────────────┘
```

**跳躍指令的長度不確定性問題：**

```asm
    JMP label        ; 這是短跳（2B）還是近跳（5B）？
                     ; 要先知道 label 的位址才能判斷
                     ; 但 label 在後面才定義...
```

解法有兩種：
1. **保守估計**：第一遍一律當成近跳（5B）
2. **多遍最佳化**：從短跳開始，若距離不夠再換成近跳（需要多次迭代）

NASM 預設使用保守估計（`JMP NEAR` 除非明確指定 `JMP SHORT`）。

### 8.2.4 第一遍追蹤範例

```
原始碼                      Pass 1 處理
─────────────────────────────────────────────────────────
                        LC = 0x0000，區段 = .text
_start:                 → SYMTAB[_start] = 0x0000
    MOV  RDI, msg       → MOV r64, imm64：10 bytes → LC = 0x000A
    MOV  RSI, msg_len   → MOV r64, imm32（LEA 替代）：7 bytes → LC = 0x0011
    MOV  RAX, 1         → MOV r64, imm32：7 bytes → LC = 0x0018
    MOV  RDI, 1         → 7 bytes → LC = 0x001F
    SYSCALL             → 2 bytes → LC = 0x0021
    MOV  RAX, 60        → 7 bytes → LC = 0x0028
    XOR  RDI, RDI       → 3 bytes → LC = 0x002B
    SYSCALL             → 2 bytes → LC = 0x002D

；切換區段
section .data           → 區段切換，LC 重設為 .data 的起始（如 0x0000）
msg:                    → SYMTAB[msg] = .data:0x0000
    DB "Hello!", 0x0a   → 7 bytes → LC = 0x0007
msg_len:                → SYMTAB[msg_len] = .data:0x0007（EQU 也可用）
    EQU $ - msg         → 常數 7，LC 不變

符號表結果：
  _start   → .text:0x0000  LOCAL
  msg      → .data:0x0000  LOCAL
  msg_len  → 常數:7        CONSTANT
```

### 8.2.5 第二遍（Pass 2）詳細演算法

```
輸入：組語原始碼 + SYMTAB
輸出：目的碼（.text, .data, ...）+ 重定位表

初始化：
    LC ← 0
    output_buffer ← 空

對每一行：
    1. 若有標號 → 跳過（已在 Pass 1 記錄）

    2. 若為機器指令：
       a. 查 OPTAB 取得 opcode
       b. 解析每個運算元：
          - 立即值 → 直接轉為二進位
          - 暫存器 → 轉為暫存器編號
          - 記憶體 → 產生 ModRM / SIB 位元組
          - 符號   → 查 SYMTAB：
              * 找到（定義在本檔案）→ 填入位址或相對位移
              * 未找到（外部符號）→ 填入 0，在重定位表記錄此位置
       c. 組合所有欄位 → 輸出機器碼

    3. 若為 DB/DW/DD：
       a. 將各運算元轉為對應的位元組序列
       b. 若含符號（如 DD some_label）→ 重定位表記錄

    4. 若為 EQU / GLOBAL / EXTERN → 不產生輸出

    5. LC += 本行的位元組數
```

### 8.2.6 第二遍翻譯範例

以 `MOV EAX, 42` 為例：

```
助記符：MOV
運算元：EAX（目的暫存器），42（立即值）

查 OPTAB：
  MOV r32, imm32 → Opcode: B8+rd（其中 rd = 暫存器編號）
  EAX 的編號 = 0
  → Opcode = B8 + 0 = B8

立即值 42 → 小端序 4 bytes：2A 00 00 00

最終機器碼：B8  2A 00 00 00
            ↑   ↑──────────
           MOV  立即值 42
```

以 `JNZ loop_label` 為例（loop_label 在前面定義，位址已知）：

```
當前 LC = 0x0013
loop_label 在 SYMTAB = 0x000A

短跳指令：EB + disp8
  disp8 = 目標位址 - (當前LC + 指令長度)
        = 0x000A - (0x0013 + 2)
        = 0x000A - 0x0015
        = -11 = 0xF5（8-bit 有號）

機器碼：75 F5（JNZ + disp8，75 是 JNZ 的 opcode）
```

## 8.3 符號表（Symbol Table）

### 8.3.1 符號表的結構

符號表記錄程式中每個符號（標號、常數、外部符號）的完整資訊：

```
符號表（SYMTAB）
┌─────────────┬──────────┬────────┬────────┬────────────┬───────────┐
│  符號名稱   │  值/位址  │  區段  │  大小  │  類型      │  可見性   │
├─────────────┼──────────┼────────┼────────┼────────────┼───────────┤
│  _start     │  0x0000  │  .text │   —    │  FUNC      │  GLOBAL   │
│  main       │  0x0040  │  .text │  128   │  FUNC      │  GLOBAL   │
│  helper     │  0x00C0  │  .text │   32   │  FUNC      │  LOCAL    │
│  msg        │  0x0000  │  .data │   14   │  OBJECT    │  LOCAL    │
│  counter    │  0x000E  │  .bss  │    4   │  OBJECT    │  GLOBAL   │
│  MAX_SIZE   │  1024    │  ABS   │   —    │  CONSTANT  │  LOCAL    │
│  printf     │  未定義   │  UNDEF │   —    │  FUNC      │  EXTERN   │
└─────────────┴──────────┴────────┴────────┴────────────┴───────────┘
```

### 8.3.2 符號的屬性

**類型（Type）：**
- `FUNC`：函式（在 .text 區段的可執行程式碼）
- `OBJECT`：資料物件（在 .data 或 .bss）
- `CONSTANT`：EQU 定義的純常數
- `NOTYPE`：未知類型（組語標號的預設）

**可見性（Binding/Visibility）：**
- `LOCAL`：只在本目的檔內可見（不能被連結器跨檔案解析）
- `GLOBAL`：全域可見（`global` 宣告的符號，可被連結器使用）
- `WEAK`：弱定義（允許被其他檔案的同名強定義覆蓋）

**狀態（Section）：**
- `.text`、`.data`、`.bss`：定義在對應區段
- `ABS`：絕對值（不需重定位的常數）
- `UNDEF`：未定義（`extern` 宣告，需由連結器解析）

### 8.3.3 符號的作用域規則

```asm
global _start       ; _start 標記為 GLOBAL（連結器可見）
extern printf       ; printf 標記為 UNDEF GLOBAL（需連結器從外部找）

_start:             ; LOCAL 符號（未宣告 global 的標號）
    call  helper    ; helper 是 LOCAL，在同一個 .o 內解析
    call  printf    ; printf 是 EXTERN，需連結器解析

helper:             ; 未宣告 global → LOCAL
    ret
```

### 8.3.4 符號表的實作方式

實際組譯器通常用**雜湊表（Hash Table）** 實作符號表，提供 O(1) 的查詢與插入：

```
雜湊函式將符號名稱映射到表格桶（Bucket）：

hash("_start") = 42 → 桶 42 → {名稱:"_start", 值:0x0000, ...}
hash("printf") = 17 → 桶 17 → {名稱:"printf", 值:UNDEF, ...}

若發生衝突（兩個符號映射到同一桶），以鏈結串列解決：
桶 17 → {printf} → {另一個衝突的符號}
```

## 8.4 重定位表（Relocation Table）

### 8.4.1 為什麼需要重定位？

目的碼（.o 檔）是**可重定位**的，也就是說程式碼中有些位址在連結時才能確定。當指令引用了：

- **外部符號**（定義在其他 .o 檔中，如 `call printf`）
- **跨區段的符號**（如 .text 中引用 .data 的 `msg`）
- **在連結後才知道絕對位址的本地符號**

這些位置在 .o 檔中先填入佔位值（通常是 0），並在重定位表中記錄「這個位置需要填入什麼值、如何計算」。

### 8.4.2 重定位表項目的結構

```
重定位表（.rel.text 或 .rela.text）
┌──────────┬──────────┬────────────────┬────────────┐
│  偏移量  │  符號索引 │  重定位類型    │  附加值    │
│  (r_offset)│(r_sym)│ (r_type)       │ (r_addend) │
├──────────┼──────────┼────────────────┼────────────┤
│ 0x0001   │  printf  │ R_X86_64_PLT32 │  -4        │  CALL printf
│ 0x000B   │  msg     │ R_X86_64_32S   │   0        │  MOV RSI, msg
│ 0x0020   │  counter │ R_X86_64_PC32  │  -4        │  ADD [counter], 1
└──────────┴──────────┴────────────────┴────────────┘
```

**欄位說明：**

- `r_offset`：需要被修改的位置（在 .text 或 .data 內的偏移）
- `r_sym`：引用的符號（在符號表中的索引）
- `r_type`：重定位類型，決定連結器如何計算最終值
- `r_addend`（RELA 格式）：附加常數

### 8.4.3 重定位類型

x86-64 常見的重定位類型：

| 類型 | 公式 | 用途 |
|------|------|------|
| `R_X86_64_64` | `S + A` | 64-bit 絕對位址 |
| `R_X86_64_32` | `S + A` | 32-bit 零擴展絕對位址 |
| `R_X86_64_32S` | `S + A` | 32-bit 符號擴展絕對位址 |
| `R_X86_64_PC32` | `S + A - P` | 32-bit PC 相對位址 |
| `R_X86_64_PLT32` | `L + A - P` | 透過 PLT 的函式呼叫 |

其中：
- `S`：符號的最終位址（連結後確定）
- `A`：附加值（Addend）
- `P`：被重定位欄位的位址

### 8.4.4 重定位的實際範例

```asm
; 在 main.o 中：
    CALL printf        ; printf 是外部符號

; 組譯後的機器碼（call 指令佔 5 bytes）：
; E8 00 00 00 00
;    ↑──────────── 暫時填 0（printf 位址未知）

; 重定位表記錄：
; 偏移量 = CALL 指令的 imm32 欄位的位址（相對 .text 開頭）
; 符號   = printf
; 類型   = R_X86_64_PLT32
; 附加值 = -4（因為 PC 相對：下一條指令位址 = 當前位址 + 4）

; 連結器執行重定位（假設 printf 在位址 0x0040_8020，
;                   CALL 指令的 imm32 欄位位於 0x0040_1001）：
; 計算值 = printf_addr + (-4) - field_addr
;        = 0x408020 + (-4) - 0x401001
;        = 0x7015（相對位移）
; 連結後：E8 15 70 00 00（填入正確的相對位移）
```

## 8.5 ELF 目的檔格式

### 8.5.1 ELF 概覽

**ELF（Executable and Linkable Format）** 是 Linux/Unix 系統的標準二進位格式，用於可重定位目的碼（.o）、共享程式庫（.so）和可執行檔。

```
ELF 目的檔（.o）的結構：

┌───────────────────────────────┐  偏移 0
│          ELF Header           │  52B（32-bit）/ 64B（64-bit）
├───────────────────────────────┤
│    .text（程式碼 Section）     │  機器指令
├───────────────────────────────┤
│    .rodata（唯讀資料）         │  字串常數等
├───────────────────────────────┤
│    .data（已初始化資料）       │  全域已初始化變數
├───────────────────────────────┤
│    .bss（未初始化）            │  只記錄大小，不佔磁碟空間
├───────────────────────────────┤
│  .symtab（符號表）             │  所有符號的資訊
├───────────────────────────────┤
│  .strtab（字串表）             │  符號名稱的字串儲存
├───────────────────────────────┤
│  .rel.text（.text 重定位表）   │  .text 中需重定位的位置
├───────────────────────────────┤
│  .rel.data（.data 重定位表）   │  .data 中需重定位的位置
├───────────────────────────────┤
│  Section Header Table（SHT）  │  所有 Section 的描述
└───────────────────────────────┘
```

### 8.5.2 ELF Header 的關鍵欄位

```c
typedef struct {
    unsigned char e_ident[16]; // 魔術數字：\x7fELF + 類別/端序/版本
    uint16_t e_type;           // ET_REL（.o）/ ET_EXEC / ET_DYN
    uint16_t e_machine;        // EM_X86_64 = 62
    uint32_t e_version;        // 1
    uint64_t e_entry;          // 程式進入點（.o 檔為 0）
    uint64_t e_phoff;          // Program Header Table 的偏移（.o 為 0）
    uint64_t e_shoff;          // Section Header Table 的偏移
    uint32_t e_flags;          // 架構特定旗標
    uint16_t e_ehsize;         // ELF Header 大小（64B）
    uint16_t e_phentsize;      // Program Header 項目大小
    uint16_t e_phnum;          // Program Header 項目數（.o 為 0）
    uint16_t e_shentsize;      // Section Header 項目大小（64B）
    uint16_t e_shnum;          // Section Header 項目數
    uint16_t e_shstrndx;       // 區段名稱字串表的索引
} Elf64_Ehdr;
```

**ELF 魔術數字（Magic Number）：**

```
e_ident[0..3] = 0x7F 0x45 0x4C 0x46  → "\x7fELF"
e_ident[4]    = 2  → ELF64（1 = ELF32）
e_ident[5]    = 1  → Little-Endian（2 = Big-Endian）
e_ident[6]    = 1  → ELF 版本 1（目前唯一合法值）
```

### 8.5.3 Section Header Table

每個 Section 在 SHT 中有一個 64-byte 的描述項：

```c
typedef struct {
    uint32_t sh_name;      // 在 .shstrtab 中的名稱偏移
    uint32_t sh_type;      // SHT_PROGBITS / SHT_SYMTAB / SHT_RELA ...
    uint64_t sh_flags;     // SHF_ALLOC | SHF_EXECINSTR | SHF_WRITE ...
    uint64_t sh_addr;      // 載入位址（.o 通常為 0）
    uint64_t sh_offset;    // 在 ELF 檔案中的偏移
    uint64_t sh_size;      // Section 的大小
    uint32_t sh_link;      // 關聯的 Section 索引（如 .symtab → .strtab）
    uint32_t sh_info;      // 額外資訊（.symtab → 第一個全域符號的索引）
    uint64_t sh_addralign; // 對齊要求（2 的冪次）
    uint64_t sh_entsize;   // 若為表格型 Section，每個項目的大小
} Elf64_Shdr;
```

**常見的 Section Type（sh_type）：**

| 常數 | 值 | 說明 |
|------|----|------|
| `SHT_NULL` | 0 | 無效（索引 0 的佔位）|
| `SHT_PROGBITS` | 1 | 程式定義內容（.text, .data）|
| `SHT_SYMTAB` | 2 | 完整符號表（含除錯資訊）|
| `SHT_STRTAB` | 3 | 字串表 |
| `SHT_RELA` | 4 | 含 Addend 的重定位表 |
| `SHT_NOBITS` | 8 | 不佔磁碟空間（.bss）|
| `SHT_REL` | 9 | 不含 Addend 的重定位表 |
| `SHT_DYNSYM` | 11 | 動態連結用的精簡符號表 |

## 8.6 單遍組譯器（One-Pass Assembler）

### 8.6.1 基本概念

一些簡單的組譯器（特別是嵌入式環境）使用**單遍組譯**：

```
限制：不允許前向參考（標號必須在使用前定義）

或者：使用「回填（Backpatching）」技術：
  1. 遇到前向參考時，在輸出中插入佔位符並記錄
  2. 後來遇到標號定義時，回頭填入正確值
```

### 8.6.2 回填演算法（Backpatching）

```
回填表（Backpatch List）：
┌──────────┬──────────┬──────────────────────┐
│ 未解析符號│ 指令位址  │ 需要填入的欄位偏移   │
├──────────┼──────────┼──────────────────────┤
│ end_label│ 0x0007   │ +1（JMP 的 disp8）   │
│ loop_top │ 0x0013   │ +1（JNZ 的 disp8）   │
└──────────┴──────────┴──────────────────────┘

當掃描到 end_label: 時（LC = 0x001A）：
  → 從回填表找出所有引用 end_label 的位置
  → 計算 disp = 0x001A - (0x0007 + 2) = 0x11
  → 回頭修改 0x0008 處的位元組為 0x11
  → 從回填表移除此項
```

## 8.7 多遍組譯（Multi-Pass）與最佳化

### 8.7.1 為何需要多遍？

兩遍組譯在某些情況下無法最佳化指令長度：

```asm
; 問題：第一遍時不知道 JMP 該用 SHORT（2B）還是 NEAR（5B）
; 若保守估計用 NEAR，可能浪費 3 bytes

    JMP label    ; 先假設 NEAR（5B），LC += 5
    ...          ; 一些指令
label:           ; 若距離 < 128，其實 SHORT 就夠
```

### 8.7.2 三遍組譯（NASM 的近似做法）

```
第一遍：計算大致的符號位址（假設所有跳躍用最大長度）
第二遍：根據符號位址，確定每個跳躍的最佳長度，重新計算 LC
第三遍：產生最終機器碼
```

NASM 使用一種稱為 **「鬆弛（Relaxation）」** 的策略：

```
1. 初始：所有跳躍假設用最短形式（SHORT）
2. 若 SHORT 不夠遠 → 改為 NEAR（5B），這使後面的 LC 都增大
3. LC 增大可能使更多跳躍需要從 SHORT 改為 NEAR
4. 重複直到沒有更多改變（收斂）
```

## 8.8 組譯器錯誤處理

### 8.8.1 常見的組譯時期錯誤

| 錯誤類型 | 範例 | 訊息 |
|---------|------|------|
| 未定義符號 | `JMP unknown_label` | `error: symbol 'unknown_label' undefined` |
| 重複定義 | 兩行都定義 `start:` | `error: symbol 'start' redefined` |
| 運算元大小不符 | `MOV EAX, RBX` | `error: mismatch in operand sizes` |
| 不合法的運算元 | `MOV [mem1], [mem2]` | `error: invalid combination of opcode and operands` |
| 立即值超出範圍 | `MOV AL, 256` | `error: immediate value out of range` |
| 未知指令 | `TYPO EAX, EBX` | `error: parser: instruction expected` |

### 8.8.2 警告（Warning）vs 錯誤（Error）

```
警告（不阻止組譯，但提示潛在問題）：
  - 標號未被使用
  - 區段對齊不理想
  - 使用了過時的語法

錯誤（阻止組譯，必須修正）：
  - 未定義的符號
  - 語法錯誤
  - 非法的指令或運算元組合
```

## 8.9 NASM 的特殊功能

### 8.9.1 多區段與自訂區段

```asm
section .text
    ; 程式碼

section .data
    ; 已初始化資料

section .bss
    ; 未初始化資料

; 自訂區段（連結器指令碼可將它放到指定位址）
section .mydata  align=64
    special_data   DQ  0, 0, 0, 0   ; 64-byte 對齊
```

### 8.9.2 `$` 與 `$$`

```asm
; $ = 目前指令的位址（位置計數器）
; $$ = 目前區段的起始位址

msg     DB  "Hello"
msg_len EQU $ - msg       ; $ - msg = 5（字串長度）

section_offset EQU $ - $$ ; 目前指令距離區段開頭的偏移
```

### 8.9.3 `TIMES` — 重複定義

```asm
; 重複定義資料
zeros       TIMES 100 DB 0    ; 100 個零 bytes（等同 RESB 100 但在 .data）
nop_sled    TIMES 10  NOP     ; 10 個 NOP 指令
boot_sign   TIMES (510 - ($-$$)) DB 0  ; 填充到 510 bytes
            DW  0xAA55        ; 主開機記錄簽章
```

### 8.9.4 `ALIGN` — 對齊

```asm
section .data
    byte_var  DB  1
    ALIGN 4                 ; 下一個資料從 4-byte 對齊的位址開始
    int_var   DD  100       ; 確保 4-byte 對齊（效能最佳）
    ALIGN 16                ; 下一個從 16-byte 對齊開始
    xmm_data  DQ  0, 0      ; SSE 操作需要 16-byte 對齊
```

## 8.10 本章小結

**兩遍組譯的核心：**
- Pass 1：建立符號表（SYMTAB），計算每個標號的位址
- Pass 2：翻譯指令為機器碼，查符號表解析前向參考，記錄外部符號到重定位表
- 前向參考是兩遍設計的根本原因；單遍組譯需要回填（Backpatching）機制

**指令翻譯的關鍵資料結構：**
- OPTAB（指令表）：助記符 → opcode + 長度規則
- SYMTAB（符號表）：名稱 → 位址 + 屬性（以雜湊表實作）
- 重定位表：記錄哪些位置含有需要連結器填寫的值

**ELF 目的碼格式：**
- ELF Header → Section Header Table → 各個 Section（.text / .data / .bss / .symtab / .rel.text ...）
- 符號表項目包含名稱、值、大小、類型、可見性（LOCAL/GLOBAL/WEAK）、所在區段
- 重定位表項目包含偏移量、符號索引、重定位類型、附加值（RELA 格式）

**連結器介面：**
- `global` 宣告使符號對連結器可見（GLOBAL）
- `extern` 宣告告知組譯器此符號在其他檔案定義（UNDEF）
- 連結器解析 UNDEF 符號，執行重定位，產生最終可執行檔
