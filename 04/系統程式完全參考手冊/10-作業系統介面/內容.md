> **本章目標：** 深入理解程式如何透過系統呼叫與作業系統核心互動，涵蓋行程管理、記憶體管理、檔案 I/O、訊號機制，以及中斷與例外的硬體處理流程。

## 10.1 使用者模式與核心模式

### 10.1.1 特權層級（Privilege Rings）

x86-64 架構定義了四個特權層級（Ring 0 ～ Ring 3），現代作業系統主要使用兩個：

```
Ring 0（核心模式，Kernel Mode）：
  - CPU 可執行所有指令（含特權指令 IN/OUT/HLT/LGDT...）
  - 可存取所有實體記憶體
  - 可設定頁面表、中斷向量表
  - 作業系統核心運行於此層級

Ring 3（使用者模式，User Mode）：
  - 不能執行特權指令（嘗試會觸發 General Protection Fault）
  - 只能存取自己的虛擬位址空間
  - 無法直接存取 I/O 埠或硬體暫存器
  - 所有使用者程式（包含 Shell、瀏覽器等）運行於此層級

Ring 1 / Ring 2：
  - 虛擬化技術有時使用（如 VMware 的舊式做法）
  - 現代 OS 一般不使用
```

```
使用者程式需要作業系統資源時，必須透過系統呼叫（Syscall）
請求核心代為執行，這是唯一合法的跨越 Ring 3 → Ring 0 的方式。
```

### 10.1.2 特權指令範例

```asm
; ── 只能在 Ring 0 執行的指令 ──
HLT                     ; 暫停 CPU
CLI                     ; 禁止外部中斷
STI                     ; 允許外部中斷
LGDT [gdtr]             ; 載入 GDT 暫存器（記憶體分段表）
LIDT [idtr]             ; 載入 IDT 暫存器（中斷向量表）
MOV CR0, RAX            ; 修改控制暫存器（如開啟分頁）
WRMSR                   ; 寫入 Model-Specific Register
IN  AL, DX              ; 讀 I/O 埠
OUT DX, AL              ; 寫 I/O 埠

; ── 在 Ring 3 嘗試執行上述任何指令 ──
;    → CPU 觸發 #GP（General Protection Fault）
;    → 控制權轉交核心，通常 OS 傳送 SIGSEGV 給程式
;    → 程式崩潰（Segmentation Fault）
```

## 10.2 系統呼叫機制

### 10.2.1 SYSCALL 指令

Linux x86-64 使用 `SYSCALL` 指令（2 bytes：`0F 05`）進入核心：

```
SYSCALL 的執行流程（硬體層面）：

1. CPU 保存目前的 RIP 到 RCX
2. CPU 保存目前的 RFLAGS 到 R11
3. 從 MSR（IA32_LSTAR）載入核心的系統呼叫處理程式位址到 RIP
4. CS 切換到核心程式碼區段（Ring 0）
5. 跳入核心的 entry_SYSCALL_64（Linux 的系統呼叫入口）

核心處理完畢後，SYSRET 指令回到使用者模式：
1. RIP ← RCX（回到 SYSCALL 的下一條指令）
2. RFLAGS ← R11
3. CS 切換回使用者程式碼區段（Ring 3）
```

### 10.2.2 系統呼叫的呼叫約定

Linux x86-64 系統呼叫使用以下暫存器（與函式呼叫約定**不同**！）：

```
輸入：
  RAX = 系統呼叫編號
  RDI = 第 1 個引數
  RSI = 第 2 個引數
  RDX = 第 3 個引數
  R10 = 第 4 個引數   ← 注意：是 R10，不是 RCX！
  R8  = 第 5 個引數
  R9  = 第 6 個引數

輸出：
  RAX = 回傳值（成功時 ≥ 0，失敗時為 -errno，如 -2 = ENOENT）

注意：SYSCALL 會破壞 RCX 和 R11
（因此系統呼叫用 R10 而非 RCX 傳第 4 個引數）
```

### 10.2.3 常用 Linux 系統呼叫

```asm
; ── 檔案 I/O ──────────────────────────────────────────────
; read(fd, buf, count) → bytes_read
MOV RAX, 0          ; sys_read
MOV RDI, 0          ; fd = 0（stdin）
LEA RSI, [buffer]   ; buf
MOV RDX, 1024       ; count
SYSCALL

; write(fd, buf, count) → bytes_written
MOV RAX, 1          ; sys_write
MOV RDI, 1          ; fd = 1（stdout）
LEA RSI, [msg]      ; buf
MOV RDX, msg_len    ; count
SYSCALL

; open(path, flags, mode) → fd
MOV RAX, 2          ; sys_open
LEA RDI, [filepath] ; path
MOV RSI, 0          ; O_RDONLY = 0
MOV RDX, 0          ; mode（open 時不需要）
SYSCALL
; RAX = 新的 fd（或負值表示錯誤）

; close(fd) → 0
MOV RAX, 3          ; sys_close
MOV RDI, [my_fd]    ; fd
SYSCALL

; ── 行程控制 ──────────────────────────────────────────────
; exit(status)（無返回）
MOV RAX, 60         ; sys_exit
MOV RDI, 0          ; 結束碼 0 = 成功
SYSCALL

; fork() → 父行程得到子行程 PID，子行程得到 0
MOV RAX, 57         ; sys_fork
SYSCALL
; RAX = 0 → 在子行程中
; RAX > 0 → 在父行程中，值是子行程 PID
; RAX < 0 → 錯誤

; getpid() → 目前行程的 PID
MOV RAX, 39         ; sys_getpid
SYSCALL

; ── 記憶體管理 ────────────────────────────────────────────
; mmap(addr, len, prot, flags, fd, offset) → ptr
MOV RAX, 9          ; sys_mmap
XOR RDI, RDI        ; addr = 0（讓 OS 選擇）
MOV RSI, 4096       ; len = 1 頁（4KB）
MOV RDX, 3          ; PROT_READ|PROT_WRITE = 3
MOV R10, 34         ; MAP_PRIVATE|MAP_ANONYMOUS = 34
MOV R8,  -1         ; fd = -1（匿名映射）
XOR R9,  R9         ; offset = 0
SYSCALL
; RAX = 配置到的虛擬位址

; munmap(addr, len) → 0
MOV RAX, 11         ; sys_munmap
MOV RDI, [my_ptr]   ; addr
MOV RSI, 4096       ; len
SYSCALL
```

## 10.3 行程管理

### 10.3.1 行程控制區塊（PCB）

作業系統為每個行程維護一個 PCB（Process Control Block），記錄：

```
PCB 的主要內容（Linux task_struct 的簡化版）：

  pid_t      pid;           // 行程識別碼
  pid_t      ppid;          // 父行程 PID
  int        state;         // RUNNING / SLEEPING / ZOMBIE / STOPPED
  mm_struct *mm;            // 記憶體映射資訊（頁面表等）
  files_struct *files;      // 開啟的檔案描述符表
  signal_struct *signal;    // 訊號處理器
  struct cpu_context regs;  // 保存的 CPU 暫存器（Context）
  unsigned long priority;   // 排程優先順序
  struct list_head tasks;   // 連結到其他 task_struct 的指標
```

### 10.3.2 Context Switch（上下文切換）

```
Context Switch 是排程器將 CPU 從一個行程切換給另一個行程的過程：

發生時機：
  - 行程的時間片（Time Slice）用完（計時器中斷）
  - 行程主動呼叫 sleep() / wait() 進入睡眠
  - 高優先序行程就緒（搶占式排程）
  - 系統呼叫完成後排程器重新評估

步驟：
  1. 保存目前行程（A）的 CPU 狀態到 PCB_A：
       PCB_A.regs = {RAX, RBX, ..., RSP, RBP, RIP, RFLAGS}
  2. 切換頁面表：CR3 ← 新行程 B 的頁面表基底位址
  3. 從 PCB_B 還原行程 B 的 CPU 狀態：
       {RAX, RBX, ..., RSP, RBP, RIP} ← PCB_B.regs
  4. 跳入行程 B 的 RIP（行程 B 從上次停止的地方繼續）

開銷：
  - 保存/還原暫存器：數十個時脈週期
  - 切換頁面表（CR3 flush TLB）：數百個時脈週期
  - 快取失效（新行程的資料不在 L1/L2 快取中）：可能數千個時脈週期
```

### 10.3.3 fork() / exec() 模式

Unix 行程建立採用 fork-exec 模型：

```c
// C 語言的 fork-exec 範例
pid_t pid = fork();

if (pid == 0) {
    // 子行程：pid = 0
    // fork() 後子行程是父行程的完整複製
    // （Copy-on-Write：位址空間暫時共享，寫入時才複製）
    execve("/bin/ls", argv, envp);
    // execve 成功後永遠不返回（替換為新程式）
    // 若到這裡代表 execve 失敗
    exit(1);
} else if (pid > 0) {
    // 父行程：pid = 子行程的 PID
    int status;
    wait(&status);   // 等待子行程結束
    printf("子行程結束，狀態：%d\n", WEXITSTATUS(status));
} else {
    // fork 失敗
    perror("fork");
}
```

```asm
; 組語實作 fork + exec
    MOV RAX, 57         ; sys_fork
    SYSCALL
    TEST RAX, RAX
    JZ   child_process  ; RAX = 0 → 子行程
    JS   fork_error     ; RAX < 0 → 錯誤
    ; 父行程：RAX = 子行程 PID
    JMP parent_process

child_process:
    LEA RDI, [path]     ; "/bin/ls"
    LEA RSI, [argv]     ; argv 陣列
    LEA RDX, [envp]     ; envp 陣列
    MOV RAX, 59         ; sys_execve
    SYSCALL
    ; 若到這裡代表 execve 失敗
    MOV RAX, 60
    MOV RDI, 1
    SYSCALL
```

## 10.4 記憶體管理

### 10.4.1 虛擬記憶體位址空間

每個行程有獨立的虛擬位址空間（x86-64 Linux 64-bit 行程）：

```
虛擬位址空間（64-bit 行程，128TB 使用者空間）

0xFFFFFFFFFFFFFFFF  ┌──────────────────────────────┐
                    │      核心虛擬位址空間          │ ← 使用者不可存取
0xFFFF800000000000  ├──────────────────────────────┤
                    │      （非標準位址空洞）        │
0x00007FFFFFFFFFFF  ├──────────────────────────────┤
                    │     Stack（向下成長）          │ ← 函式呼叫堆疊
                    │                 ↓             │
                    │          [可用空間]            │
                    │                 ↑             │
                    │     Heap（向上成長）           │ ← malloc/new
                    ├──────────────────────────────┤
                    │     共享程式庫（.so）          │ ← libc.so 等
                    ├──────────────────────────────┤
                    │     .bss（未初始化全域）       │
                    │     .data（已初始化全域）      │
                    │     .text（程式碼）            │
0x0000000000400000  ├──────────────────────────────┤  ← 程式通常載入於此
                    │     [未映射，存取 → SIGSEGV]  │
0x0000000000000000  └──────────────────────────────┘
```

### 10.4.2 分頁機制（Paging）

x86-64 使用 4 層（或 5 層）頁面表將虛擬位址轉換為實體位址：

```
48-bit 虛擬位址（目前常用）的解析：

  63     48 47   39 38   30 29   21 20   12 11       0
  ┌────────┬───────┬───────┬───────┬───────┬──────────┐
  │ 符號擴展│ PML4  │ PDPT  │  PD   │  PT   │  offset  │
  └────────┴───────┴───────┴───────┴───────┴──────────┘
             9 bits  9 bits  9 bits  9 bits  12 bits

各層頁面表（均為 512 個 8-byte 項目 = 4KB 每張）：
  CR3      → 指向 PML4 Table（Page Map Level 4）的實體位址
  PML4[i]  → 指向 PDPT（Page Directory Pointer Table）
  PDPT[i]  → 指向 PD（Page Directory）
  PD[i]    → 指向 PT（Page Table）
  PT[i]    → 指向 4KB 物理頁面的起始位址

最終實體位址 = PT[i].base + virtual_address[11:0]（頁內偏移）
```

```
TLB（Translation Lookaside Buffer）：
  快取最近使用的虛擬→實體位址轉換
  context switch 時 CR3 改變 → 大多數 TLB 項目失效
  這是 context switch 最大的開銷之一
```

### 10.4.3 mmap 的實際使用

```asm
; 配置一塊可讀寫的匿名記憶體（等同 malloc 的底層）
    MOV RAX, 9          ; sys_mmap
    XOR RDI, RDI        ; addr = NULL（讓 OS 選擇位址）
    MOV RSI, 8192       ; len = 8192 bytes（2 頁）
    MOV RDX, 3          ; prot = PROT_READ(1) | PROT_WRITE(2) = 3
    MOV R10, 34         ; flags = MAP_PRIVATE(2) | MAP_ANONYMOUS(32) = 34
    MOV R8, -1          ; fd = -1（匿名映射不需要 fd）
    XOR R9, R9          ; offset = 0
    SYSCALL
    ; 錯誤：RAX = -ENOMEM（-12）等
    ; 成功：RAX = 新分配的虛擬位址

; 修改記憶體保護（讓程式碼頁面可執行）
    MOV RAX, 10         ; sys_mprotect
    MOV RDI, [code_ptr] ; addr
    MOV RSI, 4096       ; len
    MOV RDX, 5          ; PROT_READ(1) | PROT_EXEC(4) = 5
    SYSCALL
```

### 10.4.4 stack / heap 的成長

```
Heap 成長（brk 系統呼叫）：
  malloc() 在 heap 空間不足時呼叫 brk() 或 mmap() 向 OS 索取更多記憶體

    brk(0)  → 回傳目前 heap 的結束位址（program break）
    brk(new_end) → 將 program break 設到 new_end

Stack 成長（自動，guard page）：
  Stack 超出目前大小時觸發 Page Fault
  OS 的 Page Fault 處理器判斷是否為合法的 Stack 成長
  若是 → 配置新的頁面，stack 自動擴展
  若不是（存取了非 stack 區域）→ SIGSEGV
```

## 10.5 檔案 I/O 介面

### 10.5.1 檔案描述符（File Descriptor）

Unix 系統中，所有 I/O 資源都以「檔案」的形式存取，每個開啟的資源對應一個整數**檔案描述符（fd）**：

```
預設的三個標準 fd：
  0 = stdin（標準輸入）
  1 = stdout（標準輸出）
  2 = stderr（標準錯誤）

open() 成功時回傳的 fd 從 3 開始遞增分配。

一個 fd 可以對應到：
  普通檔案、目錄、字元裝置（/dev/null）、
  socket、管道（pipe）、timerfd、eventfd ...
```

### 10.5.2 完整的檔案讀取流程

```asm
section .data
    filename   DB "/etc/hostname", 0
    newline    DB 0x0a

section .bss
    fd         RESD 1          ; 儲存 fd
    buffer     RESB 256        ; 讀取緩衝區

section .text
global _start

_start:
    ; open("/etc/hostname", O_RDONLY)
    MOV RAX, 2              ; sys_open
    LEA RDI, [filename]     ; path
    XOR RSI, RSI            ; flags = O_RDONLY = 0
    XOR RDX, RDX            ; mode（open 時無需）
    SYSCALL
    MOV [fd], EAX           ; 儲存 fd

    ; 錯誤檢查（fd < 0 表示失敗）
    TEST EAX, EAX
    JS   .open_error

    ; read(fd, buffer, 256)
    MOV RAX, 0              ; sys_read
    MOV RDI, [fd]           ; fd
    LEA RSI, [buffer]       ; buf
    MOV RDX, 256            ; count
    SYSCALL
    ; RAX = 實際讀取的 bytes 數（0 = EOF，負值 = 錯誤）

    ; write(1, buffer, bytes_read)
    MOV RDX, RAX            ; count = 實際讀取數
    MOV RAX, 1              ; sys_write
    MOV RDI, 1              ; fd = stdout
    LEA RSI, [buffer]       ; buf
    SYSCALL

    ; close(fd)
    MOV RAX, 3
    MOV RDI, [fd]
    SYSCALL

    ; exit(0)
    MOV RAX, 60
    XOR RDI, RDI
    SYSCALL

.open_error:
    ; 錯誤處理...
    MOV RAX, 60
    MOV RDI, 1
    SYSCALL
```

### 10.5.3 管道（Pipe）

```asm
; pipe(pipefd) → 建立管道
; pipefd[0] = 讀端，pipefd[1] = 寫端
section .bss
    pipefd RESD 2   ; pipefd[2]

    MOV RAX, 22         ; sys_pipe
    LEA RDI, [pipefd]   ; pipefd 陣列
    SYSCALL

    ; fork() 後：
    ; 父行程寫入 pipefd[1]，子行程讀取 pipefd[0]
    ; 或反之，實現行程間通訊（IPC）
```

## 10.6 訊號（Signal）機制

### 10.6.1 訊號的概念

**訊號（Signal）** 是 Unix 的非同步通知機制，用於通知行程發生了某個事件：

```
訊號的來源：
  - 硬體例外（Divide by Zero → SIGFPE，非法記憶體存取 → SIGSEGV）
  - 使用者按 Ctrl+C（→ SIGINT）
  - kill() 系統呼叫（kill -9 PID → SIGKILL）
  - 計時器到期（→ SIGALRM）
  - 子行程結束（→ SIGCHLD）
```

### 10.6.2 常用訊號

| 訊號 | 編號 | 預設行為 | 說明 |
|------|------|---------|------|
| `SIGHUP` | 1 | 終止 | 終端機斷開（Hangup）|
| `SIGINT` | 2 | 終止 | Ctrl+C 中斷 |
| `SIGQUIT` | 3 | 核心傾印 | Ctrl+\\ |
| `SIGILL` | 4 | 核心傾印 | 非法指令 |
| `SIGABRT` | 6 | 核心傾印 | abort() |
| `SIGFPE` | 8 | 核心傾印 | 浮點數例外（含除以零）|
| `SIGKILL` | 9 | 終止 | **無法被捕獲或忽略** |
| `SIGSEGV` | 11 | 核心傾印 | 無效記憶體存取 |
| `SIGPIPE` | 13 | 終止 | 寫入沒有讀取端的管道 |
| `SIGALRM` | 14 | 終止 | alarm() 計時器到期 |
| `SIGTERM` | 15 | 終止 | 優雅終止請求 |
| `SIGCHLD` | 17 | 忽略 | 子行程狀態改變 |
| `SIGCONT` | 18 | 繼續 | 繼續暫停的行程 |
| `SIGSTOP` | 19 | 暫停 | **無法被捕獲或忽略** |
| `SIGTSTP` | 20 | 暫停 | Ctrl+Z |

### 10.6.3 設定訊號處理器

```c
// C 語言的訊號處理
#include <signal.h>

void my_handler(int sig) {
    // 處理訊號（注意：只能呼叫 async-signal-safe 函式！）
    const char msg[] = "收到 SIGINT\n";
    write(2, msg, sizeof(msg)-1);
}

// sigaction（比 signal() 更可靠）
struct sigaction sa = {
    .sa_handler = my_handler,
    .sa_flags   = SA_RESTART,   // 系統呼叫被中斷時自動重啟
};
sigemptyset(&sa.sa_mask);
sigaction(SIGINT, &sa, NULL);
```

```asm
; 組語設定訊號處理器（sys_rt_sigaction = 13）
section .data
    sigaction_struct:
        DQ  my_handler      ; sa_handler
        DQ  0               ; sa_flags
        DQ  0               ; sa_restorer（通常不需要）
        DQ  0               ; sa_mask（128 bits = 2 × DQ）
        DQ  0

section .text
    MOV RAX, 13             ; sys_rt_sigaction
    MOV RDI, 2              ; signum = SIGINT
    LEA RSI, [sigaction_struct] ; act
    XOR RDX, RDX            ; oldact = NULL
    MOV R10, 8              ; sigsetsize
    SYSCALL

my_handler:
    ; 訊號處理器：儲存狀態後執行處理邏輯
    ; 注意：處理器不能呼叫非 async-signal-safe 的函式（如 printf）
    PUSH RBP
    ; ... 處理邏輯 ...
    POP  RBP
    RET
```

## 10.7 中斷與例外

### 10.7.1 中斷的分類

```
硬體中斷（Hardware Interrupt）：
  - 由外部裝置觸發（鍵盤、網路卡、計時器...）
  - 非同步：可在任何指令執行後發生
  - 透過 PIC/APIC 通知 CPU，CPU 查詢中斷向量表（IDT）

軟體中斷（Software Interrupt）：
  - 由程式主動觸發（如 INT 3 = 中斷點）
  - INT 0x80（舊式 Linux 系統呼叫，已被 SYSCALL 取代）

例外（Exception）：
  - 由 CPU 自動觸發，因指令執行異常
  - 分三類：
    Fault（過失）：可恢復，如 Page Fault（#PF）、除以零（#DE）
    Trap（陷阱）：指令執行後觸發，如中斷點 #BP（INT 3）
    Abort（中止）：嚴重錯誤，如雙重例外（#DF）
```

### 10.7.2 常見的 CPU 例外

| 向量 | 名稱 | 代號 | 說明 |
|------|------|------|------|
| 0 | Divide Error | #DE | 除以零 |
| 1 | Debug | #DB | 單步除錯 / 硬體中斷點 |
| 3 | Breakpoint | #BP | INT 3（軟體中斷點）|
| 4 | Overflow | #OF | INTO 指令的溢位 |
| 5 | Bound Range | #BR | BOUND 指令 |

| 11 | Segment NP | #NP | Segment Not Present |
| 12 | Stack Fault | #SS | Stack Segment 例外 |

### 10.7.3 中斷描述符表（IDT）

```
IDT（Interrupt Descriptor Table）：
  256 個項目，每個對應一個中斷向量
  由 LIDT 指令載入到 IDTR 暫存器（只有 Ring 0 可設定）

每個 IDT 項目（64-bit 模式，16 bytes）包含：
  - 處理程式的位址（分成高低兩部分）
  - 目標程式碼區段（CS selector）
  - 類型與屬性（Gate Type：Interrupt Gate / Trap Gate）
  - DPL（Descriptor Privilege Level）：允許從哪個 Ring 觸發

中斷發生時的 CPU 動作：
  1. 完成目前指令（或在某些例外下停在當前指令）
  2. 從 IDT[向量號碼] 取得處理程式位址
  3. 若從 Ring 3 進入 Ring 0：
     從 TSS（Task State Segment）載入核心 Stack（RSP0）
     PUSH SS, RSP, RFLAGS, CS, RIP（部分例外還 PUSH Error Code）
  4. 清除 IF（禁止進一步的硬體中斷，Interrupt Gate 才這樣）
  5. 跳到中斷處理程式
  6. 處理完後，IRET 還原 CS, RIP, RFLAGS 並返回
```

### 10.7.4 Page Fault 的處理流程

Page Fault（#PF）是最常見的例外，處理流程：

```
CPU 存取虛擬位址 V 時，若頁面表項目：
  - 不存在（Present bit = 0）
  - 保護違規（寫入唯讀頁面）
  - 使用者模式存取核心頁面
  → 觸發 #PF

CPU 動作：
  1. CR2 ← 造成 Page Fault 的虛擬位址
  2. 將 Error Code 壓入堆疊（說明存取類型）
  3. 跳到 IDT[14] 的處理程式（Linux 的 do_page_fault）

Linux 的 do_page_fault 處理：
  1. 讀取 CR2（錯誤的虛擬位址）
  2. 在行程的 vm_area_struct 中查找 V 屬於哪個 VMA
  3. 判斷錯誤原因：
     a. 合法的 Stack 成長 → 配置新頁面，更新頁面表，IRET 繼續
     b. Copy-on-Write → 複製頁面，更新頁面表，IRET 繼續
     c. Demand Paging（從 mmap 的檔案讀入）→ 讀磁碟，繼續
     d. 完全非法存取 → 傳送 SIGSEGV 給行程 → 程式崩潰
```

## 10.8 系統呼叫的包裝函式（libc 的角色）

### 10.8.1 C 標準庫的系統呼叫包裝

在 C 語言中，`printf` / `malloc` / `open` 等都是 C 標準庫（libc）提供的包裝函式，底層呼叫系統呼叫：

```
printf("Hello\n")  →  vfprintf()  →  write(1, ...) → SYSCALL
malloc(100)        →  brk() 或 mmap()             → SYSCALL
open("a.txt", ...) →  __open()   → sys_open        → SYSCALL
```

### 10.8.2 直接使用系統呼叫 vs libc

```asm
; 直接系統呼叫（NASM 組語）
    MOV RAX, 1
    MOV RDI, 1
    LEA RSI, [msg]
    MOV RDX, 13
    SYSCALL

; libc 包裝（C 語言）
    write(1, msg, 13);
    // 內部等同上述，但 libc 還處理了：
    // - errno 設定（RAX 負值轉成 errno）
    // - 訊號中斷重試（EINTR 處理）
    // - 緩衝（printf 是 buffered I/O）
```

### 10.8.3 errno 的機制

系統呼叫失敗時，核心回傳負值（`-ENOENT = -2`），libc 將其轉為正的 `errno`：

```c
// libc 的 open() 包裝（簡化版）
int open(const char *path, int flags, ...) {
    long fd;
    asm("syscall"
        : "=a"(fd)
        : "0"(SYS_open), "D"(path), "S"(flags)
        : "rcx", "r11", "memory");
    if (fd < 0) {
        errno = -fd;   // 設定全域的 errno
        return -1;     // 統一回傳 -1
    }
    return fd;
}
```

## 10.9 本章小結

**使用者模式與核心模式：**
- Ring 3（使用者）無法執行特權指令或直接存取硬體
- 系統呼叫（SYSCALL 指令）是唯一合法的跨越方式
- SYSCALL 保存 RIP → RCX、RFLAGS → R11，跳入核心

**系統呼叫約定（Linux x86-64）：**
- RAX = 呼叫號碼，RDI/RSI/RDX/R10/R8/R9 = 引數（注意第 4 個是 R10 不是 RCX）
- 回傳值在 RAX，失敗為 -errno

**行程管理：**
- PCB 記錄行程的所有狀態，Context Switch 保存/還原暫存器並切換頁面表（CR3）
- fork() 建立子行程（Copy-on-Write），exec() 替換程式影像

**記憶體管理：**
- 虛擬位址空間：.text / .data / .bss / heap（↑）/ mmap 區域 / stack（↓）
- 四層頁面表（PML4 → PDPT → PD → PT → 實體頁面）
- mmap 實現按需載入、匿名記憶體配置、共享記憶體

**訊號機制：**
- 非同步通知行程發生某事件
- SIGKILL(9) 和 SIGSTOP(19) 無法被捕獲
- sigaction() 設定處理器；處理器內只能呼叫 async-signal-safe 函式

**中斷與例外：**
- IDT 記錄 256 個向量的處理程式位址，LIDT 只能在 Ring 0 設定
- Page Fault（#PF）是最常見的例外，CR2 記錄造成錯誤的虛擬位址
- 合法的 Page Fault 由 OS 處理（分配頁面、COW），非法的產生 SIGSEGV
